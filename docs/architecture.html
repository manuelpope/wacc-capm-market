Architecture

Five layers, each one small, each one replaceable. The rule of the project is that complexity is added by editing existing units, never by replacing them.

The layers

browser  ──▶  api.py  ──▶  service.py  ──┬──▶  engine/     (pure)
                                                  ├──▶  providers/  (the network)
                                                  └──▶  db.py        (the cache)
ModuleIts job
api.py The routes, the query parameters and the error codes. It knows nothing about how a number is computed.
service.py The orchestration: the provider, the cache, the overrides, the analyst step and the engines, in that order.
engine/ Pure functions. They take numbers and return numbers with warnings. They never touch the network and they never read the clock.
providers/ Everything that talks to the outside: Yahoo, the news feed and the model.
db.py A thin, explicit SQLite wrapper. One short-lived connection per call.
static/ The interface. Plain HTML, CSS and JavaScript, served as files. No build step.

The store

One SQLite file, five tables:

TableWhat it holds
snapshotsThe raw fundamentals per ticker, with the fetch timestamp
overridesThe manual inputs per ticker
llm_estimatesWhat the analyst estimated, next to the snapshot it belongs to
newsThe headlines, with the timestamp of the fetch
universeThe curated ticker catalog

The cache

  • The ticker is not stored → it is computed and stored (computed).
  • It is stored but older than the TTL → it is recomputed (stale).
  • It is stored and fresh → it is served without touching Yahoo (fresh).
  • ?refresh=true → it is always recomputed (refreshed).

Three decisions worth knowing

  • The schema is created on the first use, not when the object is built. Importing the application must not create or touch the database file, because the module level app is built at import time.
  • The journal mode is set once. Changing it needs an exclusive lock that the busy timeout does not wait for, so a concurrent request would fail with "database is locked".
  • A snapshot carries a schema version. A snapshot written by an older version is fetched again instead of being read with missing fields.

Concurrency

The application answers from a thread pool, so two requests can write at the same time. Every store call opens its own short-lived connection with a busy timeout, and the write transactions are short enough to fit inside it. The suite proves it with eight parallel requests for the same ticker and with parallel reads and writes.

The tests

The suite is 120 tests and it never touches the network: the API tests inject a fake provider and a fake model.

FileWhat it holds
test_engines.pyThe WACC, the growth and the valuation, one case at a time
test_properties.pyThe invariants that must hold for any input, checked against seeded random values
test_sensitivity.pyThe grid: the axes, the base cell, the invalid cells and the fragile ones
test_api.pyThe routes, the cache, the overrides, the analyst step, and the hostile inputs
test_llm.pyThe parsing, the range validation and the provenance of the estimates
test_news.pyThe shapes of the feed, the relevance ranking and the prompt context
test_db.pyThe store, including the proof that importing does not touch the file
test_normalization.pyThe average of the last fiscal years and the trailing figure
The invariants

The property tests check, for random inputs, that the growth never reaches the discount rate, that the value falls when the discount rate rises and rises when the growth rate rises, that nothing is ever a NaN, and that the base cell of the grid is exactly the valuation.

The design record

The decisions above were not obvious, so they are written down: the feature document in odd/tasks/wacc-valuation-lab.md holds the specification, the log of what was found and the reason for each policy. It is the reason the 5% ceiling is 5% and the 3% spread is 3%.
