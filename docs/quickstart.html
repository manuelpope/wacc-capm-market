WACC Lab · documentation v1.0.0

Quick start

Install it, run it, open it. Nothing else is needed: the analyst model is optional and the tool works without it.

Install

Python 3.11 or newer, and uv:

cd projects/wacc-lab
uv venv --python 3.13
uv sync --extra dev            # or: uv pip install -e ".[dev]"

uv.lock is committed, so uv sync installs the exact set of versions this release was verified against.

Run

.venv/bin/python -m uvicorn wacc_lab.api:app --reload

Then open http://127.0.0.1:8000.

The env file

The app reads a .env file next to it when it starts, so the credentials of the model gateway do not need an export in the shell. Copy the template and fill it in: 

cp .env.example .env
WACC_LAB_LLM_BASE_URL=http://127.0.0.1:11434/v1
WACC_LAB_LLM_MODEL=qwen3.5:9b-mlx
WACC_LAB_LLM_API_KEY=

A real environment variable always wins over the file, so an export in the shell overrides it without anyone editing it. The short names of the gateway credentials file — url, model, user and MMX-API-KEY_VIRTUAL — are read as aliases of the canonical variables.

The file is never committed: .env is in .gitignore and only the template is tracked.

The first request is slow

The first analysis of a ticker downloads its statements from Yahoo Finance, which takes a few seconds. Every later request for the same ticker is served from SQLite in milliseconds, until the snapshot goes stale.

Try the API

# the curated universe
curl http://127.0.0.1:8000/api/tickers

# a full analysis
curl "http://127.0.0.1:8000/api/analysis/AAPL"

# without the analyst model and without the news
curl "http://127.0.0.1:8000/api/analysis/AAPL?use_llm=false"

# the WACC x g grid
curl "http://127.0.0.1:8000/api/analysis/AAPL/sensitivity"

Run the tests

.venv/bin/python -m pytest -q

The suite never touches the network: the API tests inject a fake provider and a fake model, and the engine tests are pure.

Run it in Docker

docker compose up --build

Then open http://127.0.0.1:8000 again. The image carries the app and its dependencies, the SQLite store lives in a volume named wacc-data, and the env file is mounted read-only at /app/.env: the app reads it with the same parser it uses outside a container, and the secrets never enter an image layer. 

docker compose logs -f wacc-lab     # the log
docker compose down                          # stop it
docker compose down -v                       # stop it and drop the store

Configuration

Everything is read from the environment, and every variable has a default.

The store and the cache

WACC_LAB_DB=/path/to/db.sqlite       # default: data/wacc_lab.db
WACC_LAB_TTL_HOURS=24                # default: 24

Where the env file is

WACC_LAB_ENV_FILE=/path/to/.env     # default: the .env next to the app

The analyst model

export WACC_LAB_LLM_BASE_URL=http://127.0.0.1:11434/v1   # Ollama, llmlite, llama.cpp, OpenAI
export WACC_LAB_LLM_MODEL=qwen3.5:9b-mlx
export WACC_LAB_LLM_API_KEY=                               # only for hosted providers
export WACC_LAB_LLM_USER=                                  # the account the request is billed to
export WACC_LAB_LLM_TIMEOUT=180
export WACC_LAB_LLM_MODE=chat                              # "completions" for llama.cpp servers
export WACC_LAB_LLM_REASONING_EFFORT=none                 # "omit" leaves the field out
export WACC_LAB_LLM_ENABLED=1

The client speaks the OpenAI-compatible API, so the same code drives Ollama, llmlite, llama.cpp and the OpenAI API. Servers built on llama.cpp answer in reasoning_content instead of content; that field is used as a fallback, and WACC_LAB_LLM_MODE=completions switches to the plain /v1/completions endpoint for those builds.

A base URL that carries only a host and a port gets the /v1 prefix of the OpenAI-compatible API. The short names of the gateway credentials file are read as aliases: url, model, user and MMX-API-KEY_VIRTUAL. The canonical name always wins.

WACC_LAB_LLM_REASONING_EFFORT=none asks the server for no reasoning, which is what a structured extraction needs. omit leaves the field out of the request, which is what a model that always thinks requires: it rejects the effort none.

WACC_LAB_LLM_ENABLED=0 turns the whole analyst step off, and so does the use_llm=false query parameter on any request.

The model is not downloaded

The tool never pulls a model. It talks to whatever is already running on the configured endpoint. If nothing answers there, the analysis still works: the missing inputs fall back to their documented defaults and the interface says which ones they were.

What the first run looks like

  1. Pick AAPL from the catalog, or type any Yahoo symbol.
  2. The status line turns green and says where the answer came from: computed and stored, served from the SQLite cache, cached snapshot was stale, recomputed or recomputed from Yahoo Finance.
  3. Four cards fill in: the summary, the WACC, the growth rate and the valuation. Below them, the inputs table, the grid, the news and the warnings.
  4. Read the warnings before you read the numbers. They say which inputs were defaulted, which caps fired and how far the trailing cash flow is from the normalized one.
